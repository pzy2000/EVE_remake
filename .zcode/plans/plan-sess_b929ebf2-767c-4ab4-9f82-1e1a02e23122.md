# 折叠屏 UI 适配优化方案(Unity 版)

## 问题根因(已确认)

截图运行的是 **Unity 版**(系统名居左、按钮居右、Overview 带标签页在左侧,与 `SpaceHud.uxml` 一致),推测经 WebGL 在微信 WebView 中打开(故有胶囊按钮)。根因:

1. `StarfallPanelSettings.asset` 的 `m_ScaleMode: 0`(ConstantPixelSize,1:1 像素),所有面板按 1920×1080 桌面基准写死像素尺寸。折叠屏运行窗口逻辑分辨率仅约 827×733(内屏)/916×391(外屏),固定像素面板占掉 50%~80% 屏幕 → UI 巨大、星空只剩窄条。
2. `SpaceHud.uss` 硬编码:`overview min-width:410px`、`target 315px`、`.modal-card 700×610`、`.starmap-card 920px`、`.module-rack left:285px/right:370px`(窄屏下被压成负宽度 → 截图中间文字串行溢出)。
3. 顶部栏 `right:16px` 被微信胶囊(●●● ⊙)遮挡;ListView 默认滚动条粗大出戏。
4. 全仓库无任何屏幕适配/断点逻辑(UI Toolkit USS 不支持 media query,需 C# 侧实现)。

## 改动内容

### 1. 全局等比缩放(核心修复)
- `UnityProject/Assets/Starfall/UI/StarfallPanelSettings.asset`:`m_ScaleMode: 0` → `1`(ScaleWithScreenSize)。参考分辨率 1920×1080、match 0.5 已写好,立即生效;三个场景共用此资产,一次修改全局生效。桌面 1920×1080 下 scale=1,现有桌面体验不变。
- 同步更新验收测试 `UnityProject/Assets/Starfall/Tests/PlayMode/StarfallPlayModeAcceptanceTests.cs:739-742`:断言改为 `ScaleWithScreenSize` + 参考分辨率 (1920,1080)(原断言"1:1 像素保证文字锐利"的意图在新模式下于 1920×1080 窗口依然成立)。

### 2. 新增响应式断点控制器
新文件 `UnityProject/Assets/Starfall/UI/StarfallResponsiveUi.cs`:
- 提供 `Attach(UIDocument, ListView overviewList = null)` 返回 IDisposable;监听 root `GeometryChangedEvent`(折叠/展开自动重算)。
- 纯静态 `Evaluate(panelW, panelH)` 计算参考空间尺寸(按 ScaleWithScreenSize 公式自行求 modeScale,不含玩家缩放系数,避免缩放滑块引起断点抖动),参考宽 <1550 或参考高 <1000 → 给 root 加 `hud-compact` 类,否则移除。
  - 验证:内屏 827×733 → 参考空间 ~1491×1321 → compact;外屏 916×391 → ~2182×931(高度不足)→ compact;桌面 1920×1080 → 不触发。
- compact 切换时同步 `overviewList.fixedItemHeight`(默认 30 ↔ compact 26,C#/USS 双处定义问题在此收口)。
- 接入点(无需改场景文件):`SpaceHudController.cs` OnEnable/OnDisable、`MainMenuUiController.cs`、`StationUiController.cs` 同样调用 Attach。

### 3. 紧凑布局样式(`SpaceHud.uss` 末尾追加 `.hud-compact` 作用域,桌面默认样式零改动)
- 面板收窄贴边:overview `min-width 290 / max-width 370`、target `315→240`、ship-status `250→206`、combat-log `335→248`;`module-rack` 左右锚点联动调整(230/262)。
- 字号/行高/icon 缩小:overview 行高 30→26、单元格 14→12px、icon 22→16px、列宽(36/56/82/54)、tab 与列头 11px、topbar 高 52→44、模块按钮 78→58px 字号 10px、target-name 21→17px。
- **微信胶囊避让**:`.hud-compact .topbar { right: 132px; }`(≈120px 胶囊区+间距),按钮左移不再被遮挡;宽屏不受影响。
- 弹窗自适应(全局,宽屏无感知):`.modal-card` 增加 `max-width:96%; max-height:88%`、`.starmap-card` 增加 `max-width:96%`,修复小屏溢出。
- **滚动条细化**(全局):隐藏 ListView scroller 上下箭头按钮、dragger 细化为 6~8px 半透明青条(类名以运行时实际样式为准实现时核对)。

### 4. 轻量视觉改(compact 作用域,不回归桌面)
- `SpaceHud.uss`/`StarfallTheme.uss`:`.hud-compact` 下用 USS 变量覆盖提升悬浮感——`--panel` 透明度 0.91→~0.78、`--line` 描边减淡、`.panel` padding 12→8、模块按钮圆角化+保留 active 状态色、topbar 按钮紧凑化。

### 5. 设置面板新增 UI SCALE 滑块
- `StarfallSettingsPanel.cs`:DISPLAY 区 quality 下方加 "UI SCALE" 滑块(0.75~1.25,显示百分比),复用现有音量滑块模式。
- `IStarfallUiHost` 增 `UiScale`/`SetUiScale`;AppRoot 实现并持久化 `PlayerPrefs "starfall.uiscale"`(仿照 `AppRoot.cs:281-289` quality 模式),运行时写 `panelSettings.scale`(该值是与 scaleMode 计算结果相乘的附加系数,共享资产一次写入三场景生效)。

### 6. 顺带兜底
- `MainMenu.uss` `.menu-card`、`Station.uss` `.station-services` 增加 `max-width:92%`,防近方形屏溢出(等比缩放后正常,纯保险)。

### 7. 测试与验证
- 更新 `AssertUiDocument` 的 PanelSettings 断言(见第 1 点)。
- 新增 `Evaluate` 纯函数测试:内屏(827,733)→compact、外屏(916,391)→compact、桌面(1920,1080)→非 compact;以及 fixedItemHeight 26/30 同步逻辑。
- 运行现有 PlayMode 测试套件全量回归;完成后在真机/微信 WebView 中按内外屏分别复核(中央星空占比目标:内屏 ≥55%,外屏 ≥60%,对比当前 10~20%)。

## 效果预估
- 内屏:面板总宽占比 867px(58%)→ 约 660 参考px(44%),且整体等比缩小后中央星空可见区域从 ~15% 提升到 55%~65%。
- 外屏:垂直方向更从容(行高/顶栏/底栏全面紧凑),星空占比 ≥60%。
- 桌面 1920×1080:默认样式与现状完全一致。

## 风险与备注
- 非整数 panel scale 下文字轻微发虚(UI Toolkit 已开 SDF 字体渲染,影响有限;玩家可用 UI SCALE 滑块回调)。
- USS 变量继承、scroller 内部类名以运行时实际为准,实现时核对。
- 触摸操作(相机旋转/缩放目前纯鼠标)不在本次范围,如需原生触控支持可后续单独立项。
- Web 版(`js/`/`css/`)不在本次范围;如需同源适配(DPR、@media 断点)另行处理。
